# BOT Point v4.1.1 — встроенный режим Render

На существующем Render Web Service при активном процессе Gunicorn запускается независимый от StaffFlow фоновый поток. Команда старта остаётся `gunicorn --bind 0.0.0.0:$PORT render_entry:app`. Автоматическая загрузка gunicorn.conf.py запускает поток только после инициализации worker, не при импорте Flask и не в master. На Render режим embedded по умолчанию; BOT_POINTS_RUNTIME_MODE=disabled отключает, external оставляет обработку отдельному worker. Вне Render по умолчанию выключен; explicit embedded — opt-in. Перезапуск/засыпание останавливает работу, не создаются внешние запросы keep-alive. История догружает пропущенное при запуске, если последняя попытка была более 15 минут назад, и затем раз в 15 минут (BOT_POINTS_AUTO_HISTORY_ENABLED=0 отключает). Для истории нужны API_ID, API_HASH, TELETHON_STRING_SESSION, CHAT_ID и THREAD_ID. Telegram Bot требует BOT_TOKEN, CHAT_ID, THREAD_ID; при отсутствии конфигурации веб-приложение остаётся доступным. Bot API хранит обновления ограниченное время, история — последние 30 дней. Межпроцессный advisory lock не допускает одновременного цикла в одной БД; любой другой бот с тем же токеном и другой БД необходимо остановить отдельно. Автозапись Google требует прежних двух подтверждающих переменных и включения в UI. Не включать запись до сверки ledger, как в README_AUTONOMOUS_V410.md. Web и отдельный worker используют тот же код, при переходе на постоянный worker установите external на web. Сроки зависят от сетевых задержек. Никаких новых платных ресурсов.
